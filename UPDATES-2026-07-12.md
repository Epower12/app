## 3. F1 Race Weekend Prediction System

Replaced the old "pick P1/P2/P3 podium" flow with a full race-weekend prediction, per a detailed spec:

**Main prediction — Top 10 finishing order**
- Players build an ordered Top 10 by tapping drivers into slots, with reorder (▲/▼) and remove (×).
- Distance-based scoring: exact position **+5**, within 1 **+3**, within 2 **+2**, correct driver anywhere else in the Top 10 **+1**.

**Bonus questions — derived + independent**
- **Race Winner** (+3) and **Full Podium** (+5 exact / +3 right three drivers, any order) are *derived automatically* from the Top 10 pick — no extra clicks needed.
- Independent picks: **Pole** (+3), **Fastest Lap** (+3), **First Retirement** (+2), **Safety Car yes/no** (+2).
- Optional extras (collapsed by default): **Most Positions Gained** (+3), **Biggest Position Loss** (+3), **Winning Margin** (+2), **Retirements Count** (+2).

**Multipliers**
- Sprint sessions score at **×0.5**.
- Organizers can flag a race as the **season finale** for **×2** on everything.

**Per-league configuration**
- Organizers can enable/disable each of the 10 bonus questions per league from `/manage` → Driver Roster tab.
- Defaults match the spec's "suggested active questions": the 6 core bonuses on, the 4 optional extras off.

**Design touches**
- Driver chips carry real F1 constructor livery colors (Red Bull navy, Ferrari red, McLaren orange, etc.).
- Same editor component (`RaceWeekendEditor`) drives both the player's prediction form and the organizer's result-entry form — just a `mode` prop.

**Files:** `lib/scoring.ts` (new functions), `lib/types.ts` (new types + `RaceBonusConfig`), `lib/migrations.ts` (new tables/columns), `app/api/race-weekend-predictions/route.ts` (new), `app/components/RaceWeekendEditor.tsx` (new), plus updates to predictions/leaderboard/manage pages and the matches API's notification logic.

## 5. News system fixes

Investigated two reported problems — wrong categories and duplicate stories — and found concrete root causes by pulling the actual live RSS feeds:

- **Miscategorization:** the "Football" category's Sky Sports feed (`/rss/12040`) turned out to be Sky's *general all-sports* feed — it was mixing in tennis, cricket, golf, and darts, all mislabeled "Football." Removed it; football keeps BBC Sport + Goal.com.
- **Esports noise:** Dexerto and Dot Esports feeds were found to be 30–53% general gaming/streamer/entertainment content with no filtering. Added a keyword allowlist scoped only to those two sources (dedicated sources like HLTV are untouched).
- **Duplicates:** the old dedup key was `hash(sport + URL)`, which can't catch the same real story covered by two different outlets at two different URLs. Added cross-source title-similarity matching (found a real example live in production: Autosport and Motorsport.com — same parent company — republishing identical stories, similarity scores 0.93 and 0.88).
- **Cleanup:** ran a one-time purge against production. Removed the historical Sky/football rows and any already-stored near-duplicates. Verified directly against the database afterward — 0 Sky Sports rows remain in the football category.
- **Files:** `lib/rssSources.ts`, `lib/news.ts`, `app/api/news/refresh/route.ts` (added an opt-in `?cleanup=1`, mirroring the existing `?purge=1`).

## Where the code lives (important)

Only the `app/` folder is a git repo (`github.com/Epower12/app`, `main` branch). Everything else — `lib/`, `content/`, `public/`, and the root config files — is **on this PC only, not in any git repository**. It ships to production purely through the Docker build (`gcloud builds submit ... .` from the project root scoops up everything, tracked or not).

**Practical implication:** if this machine is lost, the `app/` half is recoverable from GitHub, but `lib/` (the scoring engine, migrations, email, Stripe integration, the news pipeline — effectively all the business logic) and `content/` (this blog post included) are not backed up anywhere else right now.
